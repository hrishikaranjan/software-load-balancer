# Stage 4 - Prototype

Minimum prototype: `Client -> Load Balancer -> Backend servers` with TCP forwarding, round-robin, and basic health checking.
Build it in this order and test each step before the next (commit after each).

| Step | Build | Test |
|---|---|---|
| 1 | `net_utils.cpp`, `backend_server.cpp` | `./bin/backend_server 1 9001` then `echo hi \| nc 127.0.0.1 9001` (or the client with `-p 9001`) |
| 2 | `client.cpp` | `./bin/client -p 9001 -m hello` |
| 3 | `load_balancer.cpp` forwarding to one backend | client -> LB -> backend 1 |
| 4 | `router.cpp` round robin + `backend_pool.cpp` + `servers.conf` | `./bin/client -n 9` -> 1,2,3,1,2,3,... |
| 5 | basic health check (`health_checker.cpp`) | kill a backend, it disappears from rotation |

Expected prototype output for step 4:
```
[0.1] Response generated by Backend Server 1 (port 9001) | echo: demo #1
[0.2] Response generated by Backend Server 2 (port 9002) | echo: demo #2
[0.3] Response generated by Backend Server 3 (port 9003) | echo: demo #3
```
The final code already contains all of this; to show the prototype in your report, tag the commit after step 5 (`git tag prototype`).
