# Design

## 1. Modules
| Module | Files | Responsibility |
|---|---|---|
| Load balancer main | `load_balancer.cpp` | options, accept loop, request forwarding, shutdown sequence |
| Backend server | `backend_server.cpp` | TCP server, identifies itself, `HEALTH` reply, simulated failure |
| Client | `client.cpp` | interactive / multi-request / concurrent test client |
| Backend model + pool | `backend.h`, `backend_pool.*` | per-server data, config parsing, mutex-protected state machine |
| Router | `router.*` | `Router` interface, `RoundRobinRouter`, `LeastConnectionsRouter` |
| Health checker | `health_checker.*` | background probing thread |
| Thread pool | `thread_pool.*` | worker threads + queue |
| Statistics | `statistics.*` | atomic counters + summary table |
| Logger | `logger.*` | thread-safe file/console logging |
| Signal handler | `signal_handler.*` | `sigaction` setup and flags |
| Net utils | `net_utils.*` | socket wrappers (TCP listen, connect-with-timeout, send_all, recv_line, UNIX-socket listen/connect) |
| Admin server | `admin_server.*` | thread inside the balancer: `STATUS` / `CHECK` / `PING` on a UNIX domain socket (read-only) |
| Admin client | `admin_client.*` | sends admin commands and parses the `STATUS` reply (used by GUI, lbctl, tests) |
| /proc monitor | `proc_monitor.*` | CPU %, RSS, threads per process; system CPU/memory/load; find processes by name |
| GUI controller | `gui_controller.*` | all GUI logic without drawing: refresh data, start/stop processes, send request, read log |
| GUI window | `gui_main.cpp` | Xlib + Cairo window, buttons, tables (drawing and clicks only) |
| lbctl | `lbctl.cpp` | command-line version of the admin/`/proc` queries |

## 8. Design decisions
**std::thread/std::mutex vs pthreads.** Both sit on the same Linux `pthread` implementation. I chose C++11 `std::thread`,
`std::mutex`, `std::lock_guard`, `std::condition_variable` because RAII guards unlock on every return path (no leaked locks),
code is shorter and less error-prone, and `-pthread` still links the POSIX library underneath. Raw `pthread_*` would add
manual unlock/cleanup without any benefit for this project.

**Thread pool instead of thread-per-client.** Bounded memory/threads under load, no thread creation cost per request,
and a natural demonstration of producer/consumer with a condition variable.

**`poll()` with timeouts.** The accept loop wakes every 500 ms to re-check the shutdown flag, so shutdown works even if the signal
was delivered to a different thread. `connect()` is made non-blocking so a dead host cannot hang a worker.

**Signal handlers only set flags.** Only async-signal-safe operations are allowed in a handler; all real work (closing sockets, logging,
joining threads) happens in normal code. `SA_RESTART` is not set so blocking calls return `EINTR`. `SIGPIPE` is ignored and `MSG_NOSIGNAL`
is used so a vanished client cannot kill the process.

**Strategy pattern.** `Router` is an interface; adding an algorithm = one new class + one line in `make_router()`.

**Active health checks + passive detection.** Probes find failures when no traffic exists; forward failures catch crashes between probes, and
the request is transparently retried on another server.

**Hysteresis (RECOVERING).** A server needs 2 consecutive successful probes before it gets traffic (avoids flapping).

## 9. OS and architecture concepts used
- **File descriptors**: every socket, log file and the listen socket is an fd (small integer in the per-process fd table). Each path closes its fd; check with `ls /proc/<pid>/fd` or `lsof -p`.
- **System calls**: `socket bind listen accept connect send recv poll fcntl close getsockopt setsockopt mkdir kill sigaction clone(via std::thread)`; observe with `strace -f -p <pid>`.
- **Processes vs threads**: backends are separate processes (isolated address spaces, own PID); LB threads share one address space (shared heap -> need mutexes), but each has its own stack. `ps -o nlwp` shows the thread count.
- **Memory**: `Backend` records live in the shared heap (`std::vector`); each thread stack holds its own buffers; `RSS` in `ps`/`top` shows resident memory.
- **CPU/scheduling**: waiting threads (`cv.wait`, `poll`) are sleeping and use no CPU; the kernel scheduler context-switches between runnable threads. `top -H` shows per-thread CPU.
- **Hardware/software interaction**: data goes app -> kernel TCP/IP stack -> loopback device (`ip addr show lo`); `htons/htonl` convert host byte order (little-endian x86) to network byte order (big-endian); `atomic` operations map to CPU atomic instructions (`lock xadd`).

## 10. Compiler flags
| Flag | Why |
|---|---|
| `-std=c++17` | language standard (threads, atomics, `std::unique_ptr`) |
| `-Wall -Wextra -Wpedantic` | enable warnings to catch bugs early (unused variables, sign issues, non-standard code) |
| `-O2` | optimisation level that is safe and fast |
| `-g` | debug symbols for `gdb`/`valgrind` |
| `-pthread` | enable POSIX threads at compile and link time |
| `-Iinclude` | header search path |
| `-MMD -MP` | write `.d` dependency files so header changes trigger rebuilds |
